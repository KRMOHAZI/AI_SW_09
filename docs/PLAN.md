# MiniMall 구현 계획

도구: Codex. 사용자는 요구사항 구현 및 완료 후 자동 커밋을 요청했다.

## 1. 역할과 승인
실제 작업은 Codex 단일 에이전트가 수행한다. 사람의 미션별 승인·diff 검토·역할 교대는 수행되지 않았다. 제출 전 팀이 실제 검토하고 역할 기록을 보완해야 한다. 사용자 요청 범위 안에서 함수별 계획·구현·검증을 진행한다.

## 2. 작업 단위와 검증
| 미션 | 순서 | 검증 | 위험 |
|---|---|---|---|
| M1 | getCart → addToCart → changeQuantity → removeItem | test:m1 | 오류 시 불변, 합산 재고 |
| M2 | canTransition → changeStatus → createOrder | test:m2 | 모든 부족 상품 수집, 검사 후 차감 |
| M3 | payOrder | test:m3 | 동시 실패 공유, 재시도, 반환 복사 |
| M4 | cancelOrder | test:m4 | 환불 성공 후에만 재고 복원 |
| M5 | 상세 권한 → 스냅샷 → 정렬 → 페이지 → 대표명 | 재현 테스트 먼저, test:m5 | 남의 데이터 노출, 과거 가격 훼손 |
| 도전 | expirePendingOrders | test:c | 정확히 30분, 반복 실행 |

초기 실제 테스트: Node v24.19.0에서 `npm test -- --test-isolation=none`: 45개, 통과 2, 실패 40, TODO 3. 기본 npm test는 실행 환경의 하위 프로세스 문제로 파일 단위 실패만 보고하여 진단용 옵션을 사용했다. 모든 테스트를 동일 프로세스에서 실행하며 테스트 제외는 하지 않는다.

## 3. 가정과 범위
- 수량 변경의 maxAddable은 공개 테스트대로 현재 재고(대체 수량 상한), 담기는 재고에서 기존 수량을 뺀 값이다.
- 과제는 메모리·모의 PG 기반이다. 데이터베이스, UI, 실제 결제, 외부 패키지는 추가하지 않는다.
- 결제와 취소의 교차 경쟁 및 결제 중 만료의 정책은 계약에 없다. 동일 작업의 중복 방지를 보장하고, 교차 작업의 실서비스 조정은 별도 요구사항으로 남긴다.
- 실제 PG 시간 초과는 PG 성공 여부 조회·대사가 필요하지만 모의 PG 과제 범위 밖이다.
- 없는 상품의 주문 재고는 0, 표시 이름은 상품 ID로 처리한다.

## 4. 안전장치
1. 원본 공개 테스트·공통 도구·계약서·SRS를 바이트 단위 비교한다.
2. 모든 입력 검사 후 저장소를 변경하고 반환값은 복사한다.
3. 주문별 진행 중 Promise를 공유하고 finally에서 제거한다. 테스트 실행 결과를 기록하고 미션별 커밋한다.
